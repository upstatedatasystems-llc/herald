# Troubleshooting Herald

Start with the least invasive checks:

```bash
docker compose ps
python3 scripts/status.py
./scripts/install_acceptance.sh
```

Then use Telegram:

```text
/status
/ai-check
/queue
/diagnostics
```

## Pairing fails or the bot says you are unpaired

Verify that you are using the one-time code generated by the current installation.

The normal flow is:

```text
/pair <code>
```

If the installation was reset, pairing state may also have been reset.

Review:

```bash
docker compose logs --tail=100 telegram-bot
```

Do not expose the pairing code in a public log or issue.

## Voice list works but preview playback says the preview is unavailable

Voice selection and normal podcast synthesis can still work even if preview MP3s are missing.

Rebuild the preview cache while no podcast is actively synthesizing:

```bash
docker compose exec -T telegram-bot   python -m herald.services.voice_manager --prewarm
```

If the cache or manifest is stale:

```bash
docker compose exec -T telegram-bot   python -m herald.services.voice_manager --prewarm --force
```

Then retry the sample in `/voices` or `/settings`.

The preview cache is stored in the shared work volume under `/data/herald/voice_samples/`.

## A submitted URL is blocked during extraction

Herald rejects URLs that resolve to unsafe destinations such as loopback, private, link-local, or cloud metadata addresses.

Confirm that the URL is a publicly reachable HTTP/HTTPS page.

If a legitimate public page still fails, collect:

```text
/diagnostics <job-id>
```

and inspect worker logs for extraction classification.

## A job uses Secondary or Tertiary instead of Primary

Herald uses deterministic failover when the current provider cannot complete the operation within its retry/adaptation policy.

Run:

```text
/ai-check
/settings
```

Check the effective provider chain and models. Then inspect the job's diagnostics for the normalized failure category and failover position.

## AI rate limit or timeout

Rate limits, transient upstream failures, and timeouts can trigger bounded retries and then failover.

Useful checks:

```text
/ai-check
/diagnostics <job-id>
```

Host-side:

```bash
docker compose logs --tail=200 herald-worker
```

If the issue is persistent, change the provider chain or model in `/settings` rather than increasing retry limits blindly.

## Model not found or provider configuration invalid

A configured provider may be reachable while the selected model is unavailable, renamed, or not enabled for the account.

Use:

```text
/models
/ai-check
/settings
```

Confirm that the server has the required credentials in `.env` and that the model selected for that provider is valid.

## Long source triggers adaptation or takes much longer than expected

Herald can use bounded large-source adaptation when a source exceeds a provider/model context or payload limit.

This can create additional AI calls and increase elapsed time. The canonical source remains intact while Herald works from bounded intermediate representations.

Inspect job diagnostics before changing adaptation limits.

## A fixed-duration episode is shorter than requested

Target durations are planning goals, not permission to invent unsupported material.

Source mode can finish shorter than the requested target when the supplied evidence does not support safe expansion. Expanded and Topic modes have more room to synthesize because research evidence can broaden the content.

Use the diagnostics bundle to compare requested target words, evidence-supported target words, and actual words when available.

## Telegram delivery fails because the MP3 is too large

Herald enforces `TELEGRAM_MAX_AUDIO_BYTES`, which defaults to 50 MB.

If the finished MP3 exceeds the configured limit, Herald marks Telegram delivery as failed and retains the rendered file locally for administrator recovery. Herald does not silently split the MP3 into multiple Telegram files.

Check:

```bash
docker compose logs --tail=200 herald-worker
```

and use `/diagnostics <job-id>`.

## Kokoro is unhealthy or TTS times out

Check:

```bash
docker compose ps
docker compose logs --tail=200 kokoro
make smoke
```

Confirm that the Kokoro container reaches healthy state and that no host memory or disk pressure is preventing synthesis.

## Literal mode works but AI modes do not

That usually indicates an AI provider configuration or connectivity problem rather than a Kokoro problem.

Run:

```text
/ai-check
/settings
/models
```

Literal mode makes no LLM API calls, so it can remain functional when external AI credentials, quotas, or endpoints are failing.

## A job appears stuck

Check:

```text
/status
/queue
/diagnostics <job-id>
```

Then inspect:

```bash
docker compose logs --tail=300 herald-worker
docker compose logs --tail=200 telegram-bot
```

Avoid direct PostgreSQL edits until you have captured diagnostics. Herald records durable state transitions specifically to make recovery failures diagnosable.
